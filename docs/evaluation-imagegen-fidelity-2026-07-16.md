# ImageGen試験タイルの生成忠実度評価（富士・middle sector）

作成日: 2026-07-16 ／ 種別: 評価レポート ／ 対象: `public/data/tracks/fuji/imagegen_trials/`

## 要旨

生成AI（ImageGen）で作った高精細タイルを計測した結果、**「同じ場所の鮮明化」ではなく「似た場所の描き直し」**になっている。既存SRパイプラインの合格基準に照らすと桁違いの不合格（LR一貫性 **17.6dB** vs 基準30dB・SR実績41.8dB、局所シフト **p95≈2.8m** vs SR実績0.156px≈1.6cm）。車と縁石・白線の整合が命のReplay用途では、**走行ライン近傍への適用は現方式のままでは非推奨**。役割を「コース外の見栄え」に限定するか、再試行するなら**忠実度制御つき編集モード+自動レジストレーション+既存ゲート流用**をセットにする。

この結論は [image-generation-tile-cost-estimate-2026-07-16.md](image-generation-tile-cost-estimate-2026-07-16.md) の事前警告（「存在しない線を足す、線幅や縁石間隔を変える」→「ベクトル重畳が最安定、生成AIは補助限定」）を計測で裏づけた形。

## 計測方法

pipeline/.venv-sr（numpy 2.2.6 / Pillow 12.2.0）で以下を実施。スクリプトはセッションのscratchpad（一時領域）に置いたため、恒久化するなら `pipeline/` への整備が必要（提案P0-1）。

1. **位置同定**: Hann窓つき位相相関で、生成画像（512へLanczos縮小）と「旧枠A（中心6335,3883）/修正後枠B（x=5525..6037, y=3288..3800）」の各クロップを照合
2. **大域レジストレーション**: スケール0.88〜1.12を0.02刻みで走査し、各スケールで位相相関ピークとシフトを取得
3. **LR一貫性**: 生成1254→512縮小を大域シフト補償後、輝度/RGBでPSNR（周囲8pxクロップ）
4. **局所シフト**: 64pxブロック・stride 32・テクスチャあるブロックのみ（std≥0.02）で位相相関、シフト量のp50/p95/max
5. **色統計**: RGB各chの平均差・標準偏差比
6. **対照実験**: 基準画像自身を512→1254→512と往復させ、測定チェーンの上限を確認

## 計測結果

### 位置同定 — 絵は「正しい場所」を描いていたが、置かれた場所が違った

| 照合 | シフト(px) | 相関ピーク | 判定 |
|---|---|---|---|
| 生成 vs 旧枠A | (31, -152) | 0.012 | 無相関 |
| 生成 vs 修正後枠B | (-9, -8) | 0.057 | **対応**（弱い=描き直しのため） |
| 基準512 vs 枠B | (0, 0) | 0.624 | 完全一致（JPEG劣化分のみ） |
| 枠A vs 枠B（対照） | — | 0.014 | 別の場所 |

生成コンテンツは枠B（修正後の正しい位置）を描いていた。15:55時点の適用は「内容は枠B・配置は枠A」で、**枠中心間約142mずれた場所に貼られていた**（18:17の診断「センターラインから約82m・矩形内標本0点」と整合。142mは枠中心間距離、82mは意図した中盤点までの距離）。

### 生成忠実度（vs 基準512、グリッド0.2192m/px）

| 指標 | ImageGen試験タイル | 対照実験（往復） | SRパイプライン（実績/基準） |
|---|---|---|---|
| 大域整合 | **スケール0.98** + シフト(-7,-6)px ≈1.4m、ピーク0.11 | シフト(0,0)、ピーク0.98 | ずれなし（同一画素の強調） |
| LR一貫性PSNR | **17.6dB** | 45.9dB | 41.8dB（ゲート ≥30dB） |
| 局所シフト p50 / p95 / max | 4.5px / **12.8px(≈2.8m)** / 23.9px | 全ブロック 0px | 線シフトp95 0.156px ≈1.6cm（ゲート ≤0.5px、0.1m/px格子） |
| 色調 | 平均 **-9%暗**（RGB各ch約-0.09）、コントラスト+8〜14% | 差なし | 元画像に忠実 |

注記:

- 局所シフトは「位置ずれ+描き直し」の複合値（一般ブロックの位相相関）。SR側の線特化メトリクスと厳密同一ではないが、幾何が保存されていないことを示すには十分
- スケール0.98は112m枠で端部約2.2mの変位に相当。1254×1254という非定型出力サイズとあわせ、生成〜保存の手動工程でフレーミングが変わった可能性が高い
- PNGはRGB不透明・アルファ無し → 端フェザー不可、隣接SRタイルとの継ぎ目がハードエッジ化

### 目視で確認した内容改変（幻覚）

- **Coca-Colaロゴの再描画**: 向き・位置・書体が別物（商用ではブランド・商標面でも危険）
- **隣接路の赤白エッジマークが青灰色に変色**（意味論の誤り）
- **路上に存在しない車らしき物体が出現**（リプレイでは「地面に焼き付いた幽霊車」になる）
- 照明ポールの消失、縁石ブロック間隔の変更、フェンストラス形状・タイヤバリアの創作的再解釈

## 改善提案

### P0 — 再試行の前に整えるもの

1. **ゲートの自動適用**: SR側と同型のLR一貫性・局所シフト・DISTS判定を生成のたびに機械実行し、不合格タイルはSR画像のまま残す（本計測の手順を `pipeline/` にスクリプト整備）
2. **入力の情報を捨てない**: 256px縮小入力（0.44m/px相当）をやめ、512 native、できればSR後1024pxを入力に
3. **フリー生成でなく編集モード**: GPT Image 2なら `input_fidelity: high` の画像編集、Gemini系なら「変更最小」指示+マスク、ローカルならSDXL+ControlNet-tileのimg2img（strength 0.2〜0.35、RTX 3090で無料・シード固定・オフライン）
4. **生成後の自動レジストレーション**: 位相相関/ECCで相似変換を推定して補正、残差が閾値超なら棄却。生成→配置をスクリプト化し手動工程を排除
5. **色ヒストグラム一致+端フェザー**: 基準クロップへのmean/std転写（またはヒストグラムマッチ）とアルファフェザーのベイクを生成後処理に固定

### P1 — 適用方針

- **役割分担の固定**: 白線・縁石・ロゴなど位置が意味を持つものはSR+ベクトル線（`road_edges.json` 等、実装済み）が正。ImageGenは**コース外テクスチャ（草地・グラベル・スタンド・森）限定**。corridor距離の仕組みでマスク生成は容易
- **ロゴ・車両のマスク保護**: 入力からマスクし、生成後に原画素を戻す
- **実機A/Bで費用対効果を判断**: 真上クロップでなく、chase（〜5m）/TV/俯瞰の3高度で「SR+近接ディテールシェーダー(Phase 2)」と比較。chase高度では0.09m/pxの創作ディテールはミップでほぼ消え、幻覚オブジェクトだけが残る
- **12枚パイロットの合否基準を事前固定**: 例「幻覚オブジェクト0件・局所シフトp95≤2px・継ぎ目色差閾値以下。不合格ならコース外限定へ切替」というkill criterionまで先に決める（QAループが予算140回の大半を占めるため）

### P2 — 記録・ガバナンス

- `imagegen_trials/manifest.json` に**provenance**を追加: 生成モデル/バージョン、プロンプト、入力ファイル+sha256、生成日時、`aiGenerated: true`。CLAUDE.mdの画像方針「来歴とライセンスをメタデータに記録」の要求で、SR側manifest（モデル出所・sha256記録済み）とスキーマを揃える。今回の試験ではモデル・パラメータの記録が無く、本レポートでも生成条件を特定できない — これ自体が是正対象
- クレジット表示に「AI-enhanced visualization」の明示（CC BY帰属は既存継承でOK）

## 戦略評価

「情報がある場所を正確に鮮明化する」のはSR+ベクトルの領分で、生成AIが勝てるのは「情報が乏しい場所を綺麗に見せる」こと。現在の3層構成（SR 41.8dB/0.156px+ベクトル線+近接ディテール）は位置精度を守りながら見栄えを上げる正攻法であり、ImageGenはそれの置き換えではなく、コース外の質感向上という狭い役割で試すのが費用対効果でも安全。
