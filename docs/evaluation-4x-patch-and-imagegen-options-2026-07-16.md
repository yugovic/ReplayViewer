# 中盤4×試験パッチの評価と、ImageGen適用の選択肢整理

- 記録日: 2026-07-16
- 対象: `public/data/tracks/fuji/imagegen_trials/`（中盤 lap距離1,463〜1,575m、
  RealPLKSR 4×・2048pxオーバーライドタイル、WORKLOG 18:17適用分）
- 目的: ユーザー質問「このパッチは効果があるか。もっといい手はあるか。
  なぜImageGen（生成AI）を適用できないのか。API直叩きは都度課金になるのか」への回答を文書化
- 関連: [evaluation-imagegen-fidelity-2026-07-16.md](evaluation-imagegen-fidelity-2026-07-16.md)（生成版の忠実度計測）、
  [research-ground-resolution-strategy-2026-07-16.md](research-ground-resolution-strategy-2026-07-16.md)（3層戦略・実装記録）、
  [image-generation-tile-cost-estimate-2026-07-16.md](image-generation-tile-cost-estimate-2026-07-16.md)（API費用試算）

## 結論（先出し）

1. **4×パッチのアプローチ自体は有効**（忠実・極近景で鮮鋭度向上）。ただし
   **現行の1枚はトーングレーディング（18:35導入）前の旧画像から生成されている
   ため、グレード済みの周囲より明るく霞んだ四角として浮く**。このままでは逆効果。
2. 最善手は「1枚の特別扱い」ではなく、**標準パイプラインへのコア4×リング実装**
   （中心線近傍だけ0.05m/px、全周一貫）。短期はグレード済みnativeからの切り直しで可。
3. ImageGenが適用できないのは **①環境障害（sandbox helperでソース画像を渡せず
   忠実度制御つき編集モードに入れない）②フリー生成は品質ゲートを大きく外れる**
   の二段。回避はAPI直叩きだが、**サブスク枠は充当できず従量課金**（金額は小さい）。

## 1. 4×パッチの定量評価（2026-07-16 19:05計測・読み取り専用）

計測方法: パッチ実物（`middle-sector-correct-mlsr-2048.png`）と、同座標を現行
標準パイプライン（グレード済み下地→RealPLKSR×4→2×・強度0.5）で処理したものを
表示等倍（2048グリッド）に揃え、pyiqaの無参照IQAとトーン統計で比較。

| 指標 | 4×パッチ | 現行2×タイル(等倍拡大) | 判定 |
|---|---:|---:|---|
| 忠実度（LR一貫性 vs 自ソース） | **42.1dB** | （参考: SRゲート≥30dB） | 健全。幻覚なし |
| MUSIQ（無参照・高いほど良） | **53.0** | 42.3 | 極近景の鮮鋭度は向上 |
| MANIQA | **0.276** | 0.237 | 同上 |
| 平均RGB − グレード済み周囲 | **R+20.5 / G+10.8 / B−0.2** | 0（基準） | 明るく暖色に浮く |
| コントラスト（std） | 34.5 | **49.7** | パッチ側が−30%で霞む |

- 比較パネル: `Temp/trial-vs-shipped.jpg`（左=パッチ、右=現行タイル等倍拡大）。
  目視では**右（現行）の方がアスファルトの黒とラバー痕でリッチ**に見え、
  左はエッジ（縁石ブロック・白線）のみ優位。
- 原因: パッチの入力が18:35グレーディング**前**の旧 `satellite_shizuoka.jpg`
  （0.2192m/px）であるため。トーン仕上げの寄与が格子解像度の寄与を上回る、
  という本日の教訓がそのまま再現された形。

## 2. 推奨（優先順）

1. **短期**: 同座標（元画像 x=5525, y=3288, 512px）をグレード済みnativeモザイク
   （`pipeline/cache/shizuoka_ortho/native_mosaic_graded.png`、座標は8014→8782
   スケール換算）から切り直して再生成。数十秒で完了し、浮きは解消する。
2. **本命**: `enhance_track_corridor.py` に**コア4×リング**を実装 —
   中心線±30m程度は0.05m/px（2048pxタイル）、外側は現行2×。オーバーライド
   機構が不要になり、トーン・継ぎ目・出所記録が全周で一貫。ディスク増は
   +40MB程度の見込み。将来のneosrファインチューニングもそのまま適用可能。
3. **天井上げ**: neosrでグレード済みオルソを教師に自前FT（残る最大の画質札）。
4. 生成AI（ImageGen等）は**コース外の景観テクスチャ限定**とし、走行ライン近傍は
   SR＋ベクトル線を正とする方針を維持（下記ゲート通過を採用条件に）。

## 3. なぜImageGenを適用できないのか

二段の理由がある。

1. **環境障害（一次要因）**: このWindows環境ではローカル画像をImageGenツールへ
   渡す経路（sandbox helper）が壊れており、**ソース画像を条件にする
   忠実度制御つき「編集モード」に入れない**。本日複数セッションで再現
   （WORKLOG 18:17ほか。スクリーンショット目視補助も同じhelper障害）。
2. **品質（二次要因）**: helperを迂回してプロンプトのみのフリー生成で作った
   タイルは、忠実度が要求水準を大きく外れた —
   **LR一貫性17.6dB**（ゲート≥30dB、RealPLKSR実績42dB）、
   **局所位置ずれp95≈2.8m**、車の出現・ロゴ再描画・照明ポール消失などの幻覚
   （詳細: [evaluation-imagegen-fidelity-2026-07-16.md](evaluation-imagegen-fidelity-2026-07-16.md)）。
   位置が嘘をつく地面はデブリーフ用途で許容できない。

つまり「編集モードなら改善の余地はあるが、そこへ入る経路が壊れている」状態。

## 4. 実行経路と課金の整理（2026-07-16時点・要最新確認）

「API直叩き」はサブスクリプションの利用枠と別会計になる点に注意。

| 経路 | ソース画像入力 | 自動化 | 課金 |
|---|---|---|---|
| Claude環境のImageGenツール | **不可（helper障害）** | 可 | プラン枠内 |
| ChatGPT/Geminiアプリで手動編集 | 可 | 不可（手作業） | **サブスク枠内**。12枚パイロット程度なら現実的 |
| OpenAI Images API直叩き（base64入力の編集モード） | 可 | 可（パイプライン化） | **従量課金。ChatGPT Plus/Codex等のサブスク枠は充当不可** |
| Google Gemini API（Imagen系） | 可 | 可 | 従量課金（AI Studioの無料枠の適用範囲は要確認） |

- 費用感（[既存試算](image-generation-tile-cost-estimate-2026-07-16.md)より）:
  12枚パイロットで**$0.5〜3**、コリドー全周でも$5〜35程度。従量とはいえ小さい。
- **採用条件（経路によらず共通）**: SRと同型のゲートを通過した場合のみ —
  LR一貫性≥30dB / 位相相関線シフトp95≤0.5px / 色ヒストグラム一致 /
  タイル端フェザー / manifestへのprovenance記録（モデル・プロンプト・入力sha256）。
