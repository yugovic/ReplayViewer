# CLAUDE.md template: chronological work log

Copy this file to the root of another project as `CLAUDE.md`.

## Chronological work log (mandatory)

1. Use `WORKLOG.md` as the durable work history and read it before substantial
   investigation or implementation.
2. Every substantial entry uses local time: `## YYYY-MM-DD HH:MM — title`.
3. Keep entries newest-first. Inside an entry, write milestones in the order
   they occurred.
4. Record the request, decisions/evidence, changed or generated files,
   verification actually run, failures/cancellations, and unresolved work.
5. Update the same entry as work progresses; do not duplicate or rewrite
   historical facts.
6. Never record secrets, API keys, access tokens, credentials, or personal
   data.
7. Do not state that a test or visual check passed unless it was actually run.
