# トゥーン化の断念と次方針の提案（2026-07-21、07-22追記）

## 要旨

ロジックベースのトゥーン化（方法1: シェーダ/OpenCV）は3方式を実地検証した結果、
品質不足でユーザー判断により**断念・全ロールバック済み**。写真フィルタでは
セル画に必要な「色面の再設計」（鮮やかな緑・意図的な配色）に原理的に届かない。
一方、**画風の到達可能性は Gemini の1枚テストで既に証明済み**。よって次の
パイロットは画風探しではなく「その画風を119枚で崩さず量産できるか」の検証。
推奨は12地点で **(1) Gemini そのまま** と **(2) Stability Style Transfer
（Gemini の1枚を画風参照に）** の2系統を並べ、位置精度ゲートと見た目で比較
すること（費用は合計でも数百円）。あわせて **(B) ベクター描き起こしモック**
も1枚作り比較対象に加える。ローカルControlNet（方法3B）は結果待ち。

---

## 1. これまでの経緯（何を試して何がダメだったか）

| 方式 | 内容 | 結果 |
|------|------|------|
| シェーダ量子化 | 実行時に輝度6段階へポスタライズ + fwidthインク線 | ピクセル単位の量子化が写真ノイズを拾い「まだら」で汚い |
| K-means減色（焼き込み） | bilateral×3 → Lab 14色 → 最頻値フィルタ | 頻度ベースのため多数派の灰色がパレットを独占、縁石の赤・緑が消失 |
| ルールベース（焼き込み） | 青カブリ除去 → 低彩度は固定5階調グレー / 高彩度は色相12ビン保護 | 路面一様・赤白縁石は残ったが、全体の魅力が不足（品質低）と判断 |

**教訓**: 0.2m空撮オルソは冬枯れ・低彩度で、フィルタは「写真にある色」しか
使えない。トゥーンの魅力は色の**創作**にあり、決定論的処理では埋まらない。
これは計画書（方法1推し）の想定が外れた点。

ロールバックは完了済み: シェーダ一式（TOON_GLSL/uToonStrength/Toon groundトグル）
と焼き込みバリアント（satellite_toon.jpg / toonify_ortho.py）を削除。
tsc 0エラー・304テストPASS・本番ビルドPASS・実画面確認済み。

## 2. 次の選択肢

### A. 画像編集API パイロット（推奨・先行）

- **Stability AI Structure Control（約$0.05/枚）/ Style Transfer（約$0.08/枚）**
  を代表12地点に適用。2〜3設定振っても**数百円**。
- 目的: 「生成系でそもそも望む画風に届くか」を最小コストで見極める。
- 検証は計画書どおりゲートを分離:
  - 維持: ブロック位置シフト / 白線・縁石エッジ位置 / 新規物体の出現・消失
    （enhance_track_corridor.py の計測基盤を流用）
  - 参考値化: 色差 / LR一貫性 / 写真系画質スコア
- 合格したら全周展開は**タイル単位ではなく元モザイク分割 + 128pxオーバーラップ
  + 中央採用**（境界不整合対策）。119枚+再試行で予算目安 約$10前後。

### B. ベクター描き起こしモック（推奨・並行）

- 写真を変換するのではなく、**既存ベクターデータから地面を描く**:
  路面ポリゴン（road_edges）・縁石リボン（overlays.json）・ACオーバーレイ・
  OSMフィーチャを固定パレット（アスファルト1色/芝1色/縁石赤白/白線）で描画。
- 「トラックは同じ色・縁石赤白・白線くっきり」という当初要求を**確実に**満たす。
  位置精度100%・タイル境界問題ゼロ・再現性100%・API費用0円。
- コース外の背景（林・建物・観客席）だけ生成AIで作る計画書 Phase 4 の
  ハイブリッド構成と自然に接続する。

### C. ローカル ControlNet（方法3B）— Aの結果待ち

- SDXL/FLUX img2img + ControlNet（Canny/Tile/Lineart）、低denoise・固定seed・
  同一LoRA。強いトゥーン調を作れる本命だが、環境構築+調整に1〜2日、
  VRAM要件とモデル/LoRAライセンス確認が必要。
- **Aで画風の到達可能性を確認してから**着手判断するのが工数効率が良い。

## 3. 推奨実行順

1. **A + B を並行で1〜2日**: 12地点×2系統（Gemini そのまま / Stability
   Style Transfer with Gemini画風参照。合計数百円）とベクター描き起こし
   モック1枚を作る（§4-5 の役割分担による07-22修正）。
2. **Replay実画面でA/B比較**（既存の衛星バリアント切替UIに載せて確認）。
3. 判定:
   - Aが魅力的 → 全周展開（モザイク分割+オーバーラップ、ゲート運用）。
   - Aが不足・Bが好印象 → Bを本実装（+背景のみ生成AI）。
   - どちらも不足 → C（ローカルControlNet）へ工数投下。

## 4. Gemini 1枚テストの位置づけ（2026-07-22 追記）

先行して Gemini に元画像1枚を渡したテストで良好なトゥーン画像が得られており、
これが本方針の出発点。この1枚が**証明したこと/していないこと**を区別する:

- **証明済み**: この低彩度・冬枯れの空撮からでも、生成モデルなら魅力的な
  トゥーンの色面設計を「創作」できる（＝画風の到達可能性）。ロジックベース
  3方式が全滅した今、消去法でもこの証拠の重みは増した。
- **未証明（すべて量産の問題）**:
  1. **再現性** — 119枚+再試行で白線・縁石・影が毎回同じに出るか。
     Gemini は seed 制御がなく再試行ごとに絵が変わる。
  2. **タイル間の連続性** — 隣接タイルで芝の色味・路面の濃さが揃うか。
  3. **位置精度** — 12地点の計測ゲートで初めて合格と言える。過去の
     ImageGen パイロットでは幻覚（車の出現・ロゴ再描画）が実際に出ている。

結論: **画風の勝負は既についている。次のパイロットは量産検証**である。

## 5. Stability AI の強み（なぜ併走させるか、2026-07-22 追記）

Stability の強みは絵の魅力ではなく**制御性と再現性**:

1. **構造拘束が API の第一級機能** — Structure Control は輪郭・構造の保持
   強度を `control_strength` の数値で明示指定できる（ControlNet と同発想）。
   「白線と縁石は動かすな、色と質感だけ変えろ」をプロンプト頼みではなく
   仕組みで強制できる。Gemini はプロンプトで頼むことしかできない。
2. **seed 固定の決定論性** — 同じ入力+seed+パラメータなら同じ出力。タイル間
   の条件統一・後日の再実行・manifest への完全な再現条件記録が成立する。
   計画書が警告した「再試行ごとに変わる」リスクへの直接対策。
3. **ローカル移行路との連続性** — SDXL/SD3.5 の重みが公開されているため、
   API パイロット後に同系モデル+ControlNet をローカルGPUで回す方法3Bへ
   同じ技術系統のまま移行できる（API費用ゼロ化の出口）。Gemini にこの道はない。
4. **用途特化エンドポイントと明朗な従量課金** — Structure Control 約$0.05/枚、
   Style Transfer 約$0.08/枚。特に Style Transfer は「Gemini の良い1枚を
   画風参照として渡し、全タイルへ同じ画風を適用」でき、
   **Gemini の画風 × Stability の量産保証**のいいとこ取りになりうる。

弱み: ベースモデル単体の画風の魅力・賢さは Gemini（Imagen系）が上という
評価が一般的。→ だから「画風の証拠は Gemini、量産の保証は Stability」と
役割分担し、12地点パイロットで2系統を直接比較する。
